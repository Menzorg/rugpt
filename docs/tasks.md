# Таск-трекинг: пользовательские сценарии

## Обзор

Система управления задачами в RuGPT — killer-фича альфа-версии. Включает три связанных модуля:

- **Tasks** — создание и отслеживание задач
- **TaskPolls** — утренние опросы сотрудников по статусам задач
- **TaskReports** — вечерние отчёты для руководителей

Два типа пользователей: **руководитель** (is_admin=true) и **сотрудник** (обычный пользователь).

---

## Путь руководителя

### 1. Создание задачи

Руководитель создаёт задачу через UI (вкладка "Задачи") или через чат с AI-ролью.

**Через UI:**
- Кнопка "Создать задачу" → модальное окно
- Поля:
  - **Название** (обязательно)
  - **Описание** (опционально)
  - **Исполнитель** — выбор из списка сотрудников (обязательно)
  - **Дедлайн** — дата и время (опционально, ISO 8601)
- Задача создаётся со статусом `created`

**Через чат (AI-агент):**
- Руководитель пишет в чат: `@@admin_assistant Создай задачу "Подготовить отчёт за квартал" для Иванова, дедлайн — пятница`
- AI-роль с инструментом `task_create` вызывает TaskService
- Результат отображается в чате

**Что происходит после создания:**
1. Задача сохраняется в БД (таблица `tasks`)
2. Исполнитель получает in-app уведомление:
   - Тип: `new_task`
   - Заголовок: `"Новая задача: {название}"`
   - Содержание: описание задачи
   - Появляется в колокольчике (bell icon)

### 2. Просмотр задач

- Руководитель (is_admin) видит **все задачи организации**
- Фильтры: по статусу (`created`, `in_progress`, `done`, `overdue`), по исполнителю
- Может редактировать любую задачу: изменить название, описание, статус, исполнителя, дедлайн
- Может деактивировать задачу (soft delete)

### 3. Вечерний отчёт

Каждый вечер (18:00–20:00 по таймзоне организации) планировщик автоматически генерирует отчёт для каждого руководителя.

**Что видит руководитель:**
1. Уведомление в колокольчике:
   - Тип: `report`
   - Заголовок: `"Вечерний отчёт за {дата}"`
   - Содержание: `"Опросов завершено: {N} из {M}"`

2. При открытии отчёта (вкладка "Отчёты"):
   - Текстовый блок:
     ```
     Отчёт за 2026-03-16

     Опросов завершено: 3 из 5
     Опросов просрочено: 2

       Иванов И.П.: in_progress — Работаю над документом, будет готово завтра
       Петрова А.С.: done — Готово, отправила на проверку
       Сидоров О.В.: blocked — Жду данные от бухгалтерии
       Козлов Д.М.: опрос не пройден
       Новикова Е.А.: опрос не пройден
     ```
   - Структурированная таблица `task_summaries`:
     - Для каждого завершённого опроса: название задачи, исполнитель, новый статус, комментарий
     - Для просроченных опросов: имя сотрудника + пометка `poll_completed: false`

**Когда отчёт НЕ генерируется:**
- Если за день не было ни одного опроса (у сотрудников нет активных задач)

### 4. AI-инструменты для руководителя

Через чат с AI-ролью (@@) руководитель может:

| Инструмент | Что делает | Пример |
|------------|-----------|--------|
| `task_create` | Создать задачу | "Создай задачу для Петровой: ревью договора, дедлайн — среда" |
| `task_query` | Запросить список задач | "Покажи все задачи Иванова в статусе in_progress" |
| `task_update` | Обновить задачу | "Отметь задачу X как done" |

## Путь сотрудника

### 1. Получение задачи

Сотрудник получает уведомление в колокольчике:
- Заголовок: `"Новая задача: Подготовить отчёт за квартал"`
- Содержание: описание задачи
- Клик → переход к задаче

На вкладке "Задачи" сотрудник видит **только свои задачи** (фильтр по assignee_user_id).

### 2. Утренний опрос

Каждое утро (8:00–10:00 по таймзоне организации) планировщик создаёт опрос для каждого сотрудника, у которого есть активные незавершённые задачи.

**Что видит сотрудник:**
1. Уведомление в колокольчике:
   - Тип: `poll`
   - Заголовок: `"Утренний опрос по задачам"`
   - Содержание: `"У вас 3 активных задач. Обновите статусы."`

2. На вкладке "Опросы" — форма опроса (изолированный попап, НЕ в чате):
   - Заголовок: `"Утренний опрос — 2026-03-16"`, бейдж `"Ожидает ответа"`
   - Карточка для каждой активной задачи:
     - Название задачи
     - Выпадающий список статусов:
       - `"Не начата"` (not_started)
       - `"В работе"` (in_progress)
       - `"Заблокирована"` (blocked)
       - `"Готова"` (done)
     - Поле для комментария (опционально)
   - Кнопка `"Отправить опрос"`

**Что происходит при отправке:**
1. Опрос помечается как `completed`, фиксируется `completed_at`
2. Для каждого ответа: статус соответствующей задачи обновляется
3. Ответы сохраняются в JSONB-поле `responses`:
   ```json
   [
     {"task_id": "uuid", "status": "in_progress", "comment": "Работаю над этим"},
     {"task_id": "uuid", "status": "done", "comment": "Готово"}
   ]
   ```

**Время жизни опроса:**
- Опрос действителен 10 часов с момента создания (`expires_at = created_at + 10h`)
- Если сотрудник не ответил — опрос автоматически помечается как `expired`
- Просроченный опрос нельзя заполнить (бэкенд вернёт ошибку)

### 3. Просмотр истории опросов

Вкладка "Опросы" → "История опросов":
- Список всех прошлых опросов (до 30 записей)
- Каждый опрос: дата, бейдж статуса (`Выполнен` / `Просрочен`), список ответов
- Раскрытие карточки показывает: задача → статус → комментарий

### 4. Ручное обновление задач

Сотрудник может обновить статус задачи напрямую (не только через опрос):
- Вкладка "Задачи" → выбрать задачу → изменить статус
- Доступные статусы: `created`, `in_progress`, `done`

## Автоматические процессы (Scheduler)

Планировщик (`SchedulerService`) работает как фоновый asyncio task, опрашивая каждые 30 секунд.

### Всегда (каждые 30 сек)

| Процесс | Что делает |
|---------|-----------|
| `check_overdue()` | Находит задачи с прошедшим дедлайном → статус `overdue` → уведомление исполнителю: `"Задача просрочена: {название}"` |
| `expire_stale_polls()` | Находит pending-опросы с истёкшим `expires_at` → статус `expired` (без уведомления) |

### Утро (8–10 по таймзоне организации)

| Процесс | Что делает |
|---------|-----------|
| `_run_morning_polls_for_org()` | Для каждого сотрудника с активными задачами: создать дневной опрос + уведомление |

**Гарантия идемпотентности:** UNIQUE(assignee_user_id, poll_date) — один опрос в день на сотрудника. Повторный вызов не создаст дубликат.

### Вечер (18–20 по таймзоне организации)

| Процесс | Что делает |
|---------|-----------|
| `_run_evening_reports_for_org()` | Для каждого админа: собрать все опросы за день → сгенерировать отчёт + уведомление |

### Определение времени

Планировщик использует таймзону организации (`organizations.timezone`, формат IANA, например `Europe/Moscow`):

```python
local_hour = now_utc.astimezone(ZoneInfo(org.timezone)).hour
if local_hour in (8, 9, 10):   # утро
    run_morning_polls_for_org()
if local_hour in (18, 19, 20):  # вечер
    run_evening_reports_for_org()
```

## Уведомления (In-App Notifications)

Все события таск-трекинга генерируют уведомления через `InAppNotificationService`. Уведомления доступны через колокольчик в UI.

| Событие | Тип | Заголовок | Содержание | Кому |
|---------|-----|-----------|------------|------|
| Создание задачи | `new_task` | `"Новая задача: {title}"` | description | Исполнителю |
| Утренний опрос | `poll` | `"Утренний опрос по задачам"` | `"У вас {N} активных задач. Обновите статусы."` | Сотруднику |
| Вечерний отчёт | `report` | `"Вечерний отчёт за {date}"` | `"Опросов завершено: {N} из {M}"` | Руководителю |
| Задача просрочена | `task_status_change` | `"Задача просрочена: {title}"` | — | Исполнителю |

Каждое уведомление содержит `reference_type` и `reference_id` для навигации к связанной сущности (задаче, опросу, отчёту).

## Граничные случаи

| Ситуация | Поведение |
|----------|----------|
| У сотрудника нет активных задач | Утренний опрос НЕ создаётся, уведомления нет |
| Ни один опрос за день не завершён | Вечерний отчёт НЕ генерируется |
| Сотрудник не ответил на опрос | Опрос через 10ч помечается `expired` (тихо, без уведомления). В вечернем отчёте: `"опрос не пройден"` |
| Попытка ответить на просроченный опрос | HTTP 400, ошибка валидации |
| Задача переназначена другому | Новый исполнитель НЕ получает уведомление о переназначении (только при создании). Старый исполнитель теряет задачу из своего списка |
| Невалидная таймзона у организации | Утренние/вечерние задачи пропускаются для этой орг-ции (лог-warning). Фоновые проверки (overdue, expiry) продолжают работать |
| Повторный запуск утренних опросов | Идемпотентно — дубликаты не создаются (UNIQUE constraint) |

## Схема данных

### tasks

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID PK | |
| org_id | UUID FK → organizations | Организация |
| title | VARCHAR(500) | Название задачи |
| description | TEXT | Описание |
| status | VARCHAR(20) | `created` / `in_progress` / `done` / `overdue` |
| assignee_user_id | UUID FK → users | Исполнитель |
| deadline | TIMESTAMP WITH TZ | Дедлайн (опционально) |
| is_active | BOOLEAN | Soft delete |
| created_at, updated_at | TIMESTAMP WITH TZ | |

### task_polls

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID PK | |
| org_id | UUID FK | Организация |
| assignee_user_id | UUID FK → users | Кого опрашивают |
| poll_date | DATE | Дата опроса |
| status | VARCHAR(20) | `pending` / `completed` / `expired` |
| responses | JSONB | `[{task_id, status, comment}]` |
| expires_at | TIMESTAMP WITH TZ | Когда опрос истекает (created_at + 10ч) |
| created_at, completed_at | TIMESTAMP WITH TZ | |

UNIQUE(assignee_user_id, poll_date) — один опрос в день.

### task_reports

| Поле | Тип | Описание |
|------|-----|----------|
| id | UUID PK | |
| org_id | UUID FK | Организация |
| generated_for_user_id | UUID FK → users | Руководитель |
| report_date | DATE | За какую дату |
| content | TEXT | Текстовый отчёт |
| task_summaries | JSONB | Структурированные данные по задачам |
| created_at | TIMESTAMP WITH TZ | |

## Диаграмма дневного цикла

```
  08:00                     В течение дня                   18:00
    |                           |                             |
    v                           v                             v
[Scheduler]              [Сотрудник]                    [Scheduler]
    |                           |                             |
    |  Создать опрос            |                             |
    |  для каждого              |                             |
    |  сотрудника               |                             |
    |  с задачами               |                             |
    |                           |                             |
    +---> Уведомление --------> |                             |
          "Утренний опрос"      |                             |
                                |                             |
                          Открыть опрос                       |
                          Обновить статусы                    |
                          Написать комментарии                |
                          Нажать "Отправить"                  |
                                |                             |
                          Статусы задач                       |
                          обновлены                           |
                                |                             |
                                |                       Собрать все
                                |                       опросы за день
                                |                             |
                                |                       Сгенерировать
                                |                       отчёт для
                                |                       каждого админа
                                |                             |
                                |                             +---> Уведомление
                                |                                   "Вечерний отчёт"
                                |                                   для руководителя
                                |
                    [Если не ответил за 10ч]
                                |
                          Опрос → expired
                          В отчёте: "опрос не пройден"

  -------- Фоновые проверки (каждые 30 сек, весь день) --------

  check_overdue():     deadline прошёл → задача "overdue" → уведомление
  expire_stale_polls(): expires_at прошёл → опрос "expired"
```
