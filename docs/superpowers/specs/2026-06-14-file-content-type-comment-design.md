# Файлы: комментарий + тип содержимcontентого (content_type) + орг-настройка

Дата: 2026-06-14. Статус: согласовано, в реализации.
Скоуп: **инфраструктура**. RAG/AI-обвязка комментария и аналитика по типам — НЕ входят (позже, отдельно).

## Цель

При загрузке файла пользователь указывает «что это за файл»: либо свободный комментарий, либо выбирает преднастроенный **тип содержимого** (бизнес-категория «Отчёт», «Заказ» и т.п.), у которого есть название + описание. Администратор организации ведёт справочник типов. Орг-настройка решает, можно ли пользователю писать комментарий произвольно или он обязан выбрать тип из справочника.

> Терминология: `content_type` (тип **содержимого**, бизнес-категория) — отдельно от существующего `file_type` (формат: `pdf`/`docx`).

## Модель данных (движок, миграция 047)

### Новая таблица `content_types` (скоуп по org)
- `id UUID PK`, `org_id UUID FK→organizations`, `name TEXT`, `description TEXT`,
  `is_active BOOLEAN DEFAULT true`, `created_at`, `updated_at`.
- Уникальность `(org_id, lower(name))` среди активных.
- Удаление — **мягкое** (`is_active=false`); файлы могут ссылаться.
- Ведёт **только админ** (`is_admin`). Системной строки «Вручную» нет.

### `user_files` +2 колонки
- `comment TEXT NULL`
- `content_type_id UUID NULL REFERENCES content_types(id) ON DELETE SET NULL`

Семантика комбинаций:
- `content_type_id` задан → `comment` = **дословное** описание этого типа.
- `content_type_id` NULL + `comment` непустой → **«Вручную»** (произвольный/правленый текст).
- `content_type_id` NULL + `comment` пустой → ничего не указано.

### `organizations` +1 колонка
- `file_manual_comment_allowed BOOLEAN NOT NULL DEFAULT true`
  - `true` — «Вручную» разрешена (свободный режим).
  - `false` — «Вручную» запрещена: обязателен реальный тип, комментарий = его описание дословно.

## Инвариант и валидация (на сервере, в `upload`)

Вход: `comment` (optional), `content_type_id` (optional).

1. `content_type_id` задан → должен быть активным типом этой org; **сервер сам ставит `comment = type.description`** (клиентский `comment` игнорируется). Гарантирует «тип задан ⇒ comment = описание типа».
2. `content_type_id` NULL → режим «Вручную»: `comment` берём от клиента as-is (может быть пусто).
3. Если `file_manual_comment_allowed = false` → NULL запрещён (нужен реальный тип), иначе `400`.
4. Edge: режим запрета + нет активных типов → загрузка невозможна, внятная ошибка (админу — «заведите типы в Настройках»).

## API (движок)

- `content_types` CRUD — **admin-only**:
  - `GET /content-types?include_inactive=` — список (picker: только активные; настройки админа: все).
  - `POST /content-types` — создать.
  - `PATCH /content-types/{id}` — name/description/is_active.
  - `DELETE /content-types/{id}` — мягкое удаление (`is_active=false`).
- Орг-флаг `file_manual_comment_allowed` — через апдейт организации; отдаётся фронту (org-данные / `/config`).
- `POST /files/upload` — +form-поля `comment`, `content_type_id` + валидация выше.
- Ответы по файлам (`FileResponse`) — +`comment`, `content_type_id`, `content_type_name`.

## Вебклиент

- Relay-маршруты (ZT): `content_types` CRUD, org-флаг, upload +поля (passthrough).
- **Настройки → новый раздел «Файлы»** (admin-only): тумблер «Разрешить произвольный комментарий» + CRUD-список типов (название + описание, добавить/править/деактивировать).
- **Форма загрузки:** дропдаун «Тип содержимого» (активные типы + «Вручную», если разрешена) + textarea «Комментарий».
  - Выбрал реальный тип → текст подставился из описания; начал править → выбор сам переключается на «Вручную» (`content_type_id`→NULL).
  - Режим запрета (`false`): пункта «Вручную» нет; comment read-only = описание выбранного типа.
- **Показ:** в карточке/списке файла — тип содержимого (или «Вручную») + комментарий.
